How the "Clear saved import" password works
===========================================

Factory default (first install)
-------------------------------
The built-in default is **1234** (constant `CLEAR_SAVED_IMPORT_PASSWORD` in `src/App.jsx`).

The first time you open the Clear dialog, a one-time English note explains this. After you enter the
correct current password, the app asks you to set a **new** password (and confirm it) before erasing
data. That new value is saved in the browser under localStorage key:

  route-planner:v1:clear-import-password-custom

Clearing import data does **not** remove that key, so your chosen password stays for next time.

Changing the password later
----------------------------
In the app:
- Use **Clear saved import** with your **current** saved password (the one you set earlier, not
  necessarily 1234).
- The flow is: verify password → confirm erase (and set a new password only on the very first setup
  when no custom password exists yet).

For **team / deployment** overrides without using the in-app flow, you can still change the source
constant:

1. Open `src/App.jsx`
2. Find:  const CLEAR_SAVED_IMPORT_PASSWORD = '1234';
3. Replace `1234` with your deployment default, rebuild, and redeploy.

Notes
-----
- Custom passwords set in the app live in localStorage on that machine/profile; they are not in Git.
- Do not commit real production secrets in source; if the repo is public, prefer per-user in-app
  passwords or environment-specific builds.
